## Featured Projects

### 🌾 AgroConnect 2.0 — Individual Project

**Problem I focused on:** Agricultural marketplaces need more than product listings. Trust between users, farmer verification, different participant roles, delivery, payments, and access to fair pricing all have to work together for the platform to be useful in the real world.

I built **AgroConnect 2.0** as a full-stack agricultural marketplace connecting multiple participants including buyers, farmers, fertilizer sellers, delivery partners, verification employees, and administrators.

A major problem I worked on was **preventing users from simply claiming to be farmers**. The platform includes a farmer-verification workflow using supporting evidence such as farm information, images/video, location details, and review by an assigned verification employee. Unverified farmers are restricted from publishing produce.

Other areas I worked on include:

- Role-based registration, authentication, dashboards, and permissions
- Farmer product listings and buyer purchasing flows
- Fertilizer seller and delivery workflows
- Cart, orders, payments, and notifications
- Real-time communication using Socket.IO
- Cloud-based media handling
- AI-assisted pricing logic with a clearly identified fallback when transaction history is unavailable
- CI/CD, frontend deployment, and backend deployment
- Security improvements around protected routes and sensitive verification data

**Tech used:** React, Vite, Node.js, Express, MongoDB, Mongoose, Socket.IO, Cloudinary, GitHub Actions, Vercel, Render

### 💊 Tata 1mg — Collaborative Kalvium Project

**Type:** Team project completed with a team provided through the Kalvium community.

This project taught me something that successful demos alone cannot teach.

Our first version was **rejected during the project review**. Instead of treating that rejection as the end of the project, I took the feedback seriously, looked at what was missing, learned from the weaknesses in the earlier attempt, and worked on rebuilding the project with new inputs and a better approach.

My main contribution was on the **backend side of the Next.js project**, while working within a collaborative team environment. The rebuild required me to understand code that was not entirely written by me, coordinate with teammates, solve implementation problems, and improve the project based on review feedback.

What I took from this project:

- A rejected solution can still become a valuable engineering lesson
- Feedback is useful only when it changes the next implementation
- Team projects require communication and ownership, not just individual code
- Rebuilding often produces a better understanding than getting everything right the first time
- Success is not avoiding mistakes — it is responding to them constructively
